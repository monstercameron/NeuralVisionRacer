# Mini-Splatting: spatial redistribution and importance-weighted simplification

**Decision: defer for current SOG assets; prototype only if original multi-view captures and camera poses are available.** Mini-Splatting directly targets fewer Gaussians, but its central contribution is a retraining/reconstruction pipeline that redistributes splats from images and depth, not a drop-in optimizer for an already-authored SOG v2 stream.

## Technique and evidence

Mini-Splatting (Fang & Wang, ECCV 2024; arXiv:2403.14166) treats the centers of 3D Gaussians as a point cloud and addresses both clustered overlap and under-reconstructed blurry regions. It first densifies with (1) blur split: during training, find oversized Gaussians that dominate maximum-contribution pixels over an image and split them; and (2) depth reinitialization: use a depth estimate selected from the maximum-contribution Gaussian's ellipsoid midpoint, reproject it to world points, and periodically reinitialize from sampled multi-view points. It simplifies by binarizing Gaussian weights using a threshold, then importance-weighted stochastic sampling rather than deterministic deletion; this is intended to preserve spatial coverage and avoid deleting neighboring Gaussians together. `Mini-Splatting-C` adds transform coding and ZIP for storage, while the main method reduces count. [Paper](https://arxiv.org/abs/2403.14166), [official repository](https://github.com/fatPeter/mini-splatting).

The paper reports Mip-NeRF 360 mean-count results for original 3DGS* of 3.35M splats and Mini-Splatting of 0.49M, with SSIM 0.815→0.822, PSNR 27.47→27.30 dB, LPIPS .216→.217. Its Mip-NeRF outdoor resource table reports 4.86M→0.57M and 98→410 FPS, render peak GPU memory 2.79→0.40 GB; indoor 1.46M→0.40M and 151→362 FPS, 1.07→0.35 GB. Training and rendering measurements use an RTX 3090 except the separately labeled GTX1060 run; memory is measured through PyTorch CUDA allocator. The evaluation uses the 3DGS dataset train/test splits and image resolutions, and modifies the CUDA rasterizer to emit Gaussian indices and depth points. The authors report that Tanks & Temples PSNR can decrease because their depth strategy does not model large sky regions well. These results are not WebGPU browser or game measurements. [Paper, experiments and resource table](https://arxiv.org/abs/2403.14166).

The quality-prioritized `Mini-Splatting-D` omits simplification and retains 4.69M splats on Mip-NeRF 360, with SSIM .832, PSNR 27.54 and LPIPS .175; this is evidence that their densification can improve the trained reconstruction, not a count reduction. Their main Mini-Splatting schedule runs 30K iterations, densifies to 15K and simplifies at 15K and 20K. It withholds SH during densification and only enables/increases SH after simplification to save training memory. [Paper](https://arxiv.org/abs/2403.14166).

## Fit to NeuralVisionRacer

The game's existing SOG v2 pipeline already carries WebP-compressed and codebook-quantized center/scale/SH data, decodes incrementally, and streams pre-authored per-leaf LOD chunks into a bounded pool. It has already reduced per-splat upload payload from 36 to 28 bytes and removed duplicate center textures. Existing automatic LOD selection and fades address distant detail. Mini-Splatting-C's added transform+ZIP storage compression overlaps these wins and does not inherently reduce raster work; only its changed point distribution and reduced count can address count, sorting and overdraw. The current documented bottleneck is count/coverage/alpha overdraw. [performance notes](../../performance.md), [SOG v2 decode](../../../crates/splat-render/src/sog.rs), [LOD streaming](../../../crates/splat-render/src/stream.rs).

A faithful pipeline requires original multi-view imagery and calibrated poses, because it optimizes image reconstruction, generates depth maps and resamples reprojected points. Existing SOG bundle geometry/attributes alone lack those observations. A modified renderer would need to derive the dominant-contributor ID and ellipsoid midpoint depth; then training would rebuild centers, covariance/scales, opacity and color/SH. Thus it is not a safe per-chunk SOG simplifier. If source footage/poses are not retained, defer rather than guessing with only current splats. CUDA may be used offline for training, while the resulting asset can be converted to existing SOG v2 and rendered by the portable WebGPU runtime.

The car asset is the highest-risk subject. Mini-Splatting's sampled redistribution alters centers, covariance, opacity and SH, and has no notion of wheel index, body panel, moving part, clearcoat, or shadow role. It could merge/sparsify thin spokes, tire tread, mirrors and body edges, or place newly initialized samples across foreground/background boundaries because alpha-blended depth is noisy. The method's own paper demonstrates that naive blending depth collapses/misaligns surfaces and harms PSNR; it instead requires custom maximum-contribution depth logic. For a moving car, a static multi-view reconstruction also cannot automatically preserve the existing per-Gaussian wheel deformation mapping. A vehicle experiment would need rigid/wheel segmentation and semantic constraints around those indices, or should exclude the car entirely.

For static environments, it could generate new SOG LOD assets if captured training views cover the whole driveable route and adjacent viewpoints. Generate each existing streaming leaf/LOD from a consistent scene-level reconstruction and preserve tile boundaries/metadata. Avoid independently resampling adjacent chunks without shared boundary constraints: seams, duplicated/missing splats and LOD fade mismatch are plausible. If counts are lowered while keeping the same high-detail leaf/LOD semantics, the existing LOD selection and crossfade path remains applicable. Measure if the level becomes materially faster; the paper's renderer and rasterizer differ from this WebGPU engine.

## Risks, licensing and unknowns

- Sampling improves point distribution in their benchmarks, but does not guarantee preserved tiny high-contrast structures. Their reported large point-count drop is a scene-average tradeoff, not a quality guarantee for wheel spokes or narrow race-scene details.
- Mini-Splatting reconstruction can increase count during densification before simplifying. Peak training memory remains meaningful: authors report outdoor Mini-Splatting training peak GPU memory 2.61 GB vs 7.45 GB for 3DGS on RTX3090, but this is not a runtime budget for this engine.
- Depth reinitialization assumes useful image coverage and accurate poses. Sky, reflective/glass bodywork, motion blur, occlusion boundaries and moving objects are difficult inputs. The paper documents sky-related degradation on Tanks & Temples.
- Official scripts require Python/PyTorch/CUDA 11.6 and modified CUDA rasterizer capabilities; this is offline-only work. It is not directly portable at training time, but the asset output can remain standard SOG for runtime portability.
- The GitHub repository has no explicit license file surfaced in its root listing; it acknowledges/builds on GraphDeco 3DGS. The upstream GraphDeco software license is non-commercial research/evaluation only. Treat code reuse as rights-blocked pending license verification/permission; do not copy code into the game. The paper is an algorithm reference, not a software license. [Repository](https://github.com/fatPeter/mini-splatting), [official upstream 3DGS license](https://github.com/graphdeco-inria/gaussian-splatting/blob/main/LICENSE.md).

## Smallest useful prototype and gates

First confirm whether the original static level imagery and camera poses for Saburi and Delft are available. If so, select one static, bounded environment leaf with broad held-out camera coverage and no dynamic vehicle. Train a Mini-Splatting candidate offline from those views; retain baseline and candidate SOG conversions, and generate a matched-count comparison (same target counts for Mini-Splatting and simple pruning). Keep the full detail configuration and viewport unchanged. Include saved training/test view splits and the exact output count.

Gate on held-out images from unseen camera positions, not only training views: SSIM/LPIPS and pixel residuals, visual inspection for holes/ghosting at thin railings, wires, signs, foliage and repeated architectural edges, then drive-path continuity and LOD transitions. In the browser, compare identical WASM/WebGPU build, 1280×720 canvas, effects, camera trace and LOD controls; record per-pass GPU timing, sort cost, resident bytes, upload/decode/cold-load peaks, and frame distributions. Require a repeatable real-browser gain or memory/load improvement with accepted held-out quality and no resolution/detail/effect changes. Do not translate 410 FPS on RTX3090 into an expected game frame rate.

If no original capture/pose set exists, defer this technique for this project's existing level assets. Keep it as a candidate for future level capture authoring rather than spending time attempting an unsupported SOG-only port.
