# TileGS: tile-local depth binning

**Research date:** 2026-10-26
**Scope:** rasterization, sorting, and overdraw for the Rust/WASM + WebGPU/WGSL renderer. This is a research assessment; no source implementation or browser benchmark was run.

## Recommendation

TileGS is the stronger performance candidate of the two reviewed here because it directly targets long per-tile candidate traversal and geometry-attribute traffic, and preserves the baseline compositing output to reported numerical noise. The useful idea is tile-local coarse depth binning followed by selective exact repair. The reported end-to-end gain is modest (6.9% on RTX 4090 and 9.4% on RTX 1000 Ada), although the raster-kernel gain is 1.44x. This is promising enough for a focused prototype if investigation confirms the current hardware quad draw is spending substantial time on fragment overdraw/attribute fetches.

It is not a drop-in sort tweak. The current renderer delegates per-pixel coverage and blending to the graphics rasterizer; TileGS is a one-block-per-tile compute rasterizer with tile-bin list construction, barriers/staging, and per-pixel accumulation. **Inference:** converting to it will likely replace color draws and require additional compute-produced depth outputs. If retaining the existing indexed draws and depth prepasses is necessary, the gains may be much smaller than the paper's.

## Method

TileGS starts from Gaussian/tile intersection entries with baseline depth keys, estimates a robust clipped depth range, then assigns each entry to one of 64 logarithmic depth bins within its tile. A count/atomic-scatter and prefix-sum build a tile-bin-major stream. Entries within each bin are not inherently sorted; selected segments are repaired back to original exact baseline order (the paper uses fixed segment thresholds and a repair budget up to 25% of entries). Rasterization then scans each tile's front-to-back concatenated bins using the baseline alpha-compositing equation, candidate contribution tests, and early termination. This localizes candidate traversal while keeping close/ambiguous segments exactly sorted. Default “No-GW” avoids materializing geometry sidecars and fetches attributes by Gaussian id from original arrays.

Unlike StopThePop, TileGS is not primarily correcting the Gaussian depth model. Its target is traversal efficiency and data traffic in standard tile-based 3DGS.

## Author claims and evidence

Tan, Turkulainen, Ilola, Rezazadegan Tavakoli and Kannala, *TileGS: Tile-Local Depth Binning for Gaussian Splatting Rasterization*, arXiv:2609.03613, submitted September 3, 2026. Across nine scenes on desktop and laptop Ada GPUs, authors report mean 1.44x raster-kernel speedup on RTX 4090 and end-to-end frame speedups of 1.069x on RTX 4090 and 1.094x on RTX 1000 Ada over gsplat, with |Delta PSNR| < 0.001 dB, |Delta SSIM| < 0.001 and |Delta LPIPS| < 0.001. Full-suite RTX 4090 profiling says total SASS thread instructions fall 1.26x while DRAM traffic rises; authors attribute the gain to reduced effective traversal rather than lower traffic or higher occupancy.

A supplementary synthetic scale-up on one high-workload bicycle view reports at 30M emitted entries 1.71x sort/reordering and 1.42x raster gains but only 1.09x total. At 5M entries it reports 1.11x total. These are CUDA event timings on a locked RTX 4090; the paper notes total gains are smaller/nonmonotonic because non-raster overhead remains. The research is recent and its comparison baseline is gsplat's optimized CUDA implementation, not a browser WebGPU engine with separate prepasses, car, DOF, post effects and streaming.

## Fit with this renderer

Local architecture facts: [performance notes](../../performance.md) report roughly 2.35M Saburi / 5.15M Delft resident level splats plus a 648,207-splat car. The renderer has one GPU radix sort per scene, five 4-bit passes sorting top 20 depth-key bits, and indexed quads with shared decoded centers. It merges level chunks to produce one global level order; car sorting remains separate. Two cross-object depth prepasses support mutual occlusion while preserving each object's self-blending order. Dynamic wheel centers are compute-deformed. LOD crossfades use splat opacity. Full-screen DOF/post/sharpening consume the level/car depth textures. Existing browser timestamps may overlap and should not be summed; use complete frame time and operation counts.

- **Assets:** Existing SOG V2 files can remain unchanged in principle. TileGS reorders emitted Gaussian/tile IDs and retains original attributes; it does not require retraining. **Inference:** a renderer implementation needs projected Gaussian bounds/depth and color/opacity/covariance in GPU-accessible arrays. Existing decoded centers and SOG-backed attributes could feed those, but current vertex-only derivation may need to be moved into compute or duplicated as a compact projected-attribute buffer.
- **WebGPU feasibility:** The algorithm maps naturally to compute passes (depth-range selection, bin counts, prefix scan, scatter, repair, tile traversal), but the published implementation uses CUDA. WebGPU supports workgroup storage and integer atomics, so count/scatter is plausible. However there is no portable CUDA warp intrinsic/shared-memory execution guarantee; large per-tile staging and data-dependent repair may have varying performance. The current eight-storage-buffer portability budget constrains binding layout. Capacity, dispatch size, workgroup memory and binding limits need checking on the project's minimum supported browsers/adapters. Atomic scatter order is nondeterministic; exact-repair segments restore their order, while untouched coarse bins intentionally can differ from exact global blending. Authors' near-zero image deltas are evidence only for their tested models and GPU implementation.
- **Overdraw:** It can skip candidates by contribution and terminate pixels front-to-back; bins may also group closer depth ranges. It does not necessarily reduce geometric coverage or the number of actually contributing translucent splats. **Inference:** since the app already uses sorted hardware raster quads and depth prepasses, measured win depends on whether fragment overdraw/attribute evaluation dominates versus compute construction costs.
- **Transparency/correctness:** Same baseline alpha-compositing equations are used, but order inside unrepaired bins is arbitrary atomic-scatter order. The exact repair policy is essential; bins alone are not exact transparency. Establish pixel-difference bounds per scene and inspect temporal instability under movement. The paper's numerical-noise match must not be treated as byte equivalence here.
- **Multiple objects:** Build independent lists for merged level and car so the current two-way depth-test semantics survive. **Inference:** separately binning chunks would recreate the current cross-chunk sorting defect; the level should be merged before tile-list construction. Do not combine car with level without a correct equivalent of the two depth textures and own-object blending.
- **Animated wheels:** Reproject/rebin the car when wheel centers change; stable level lists can be reused only while camera/projection and level transforms remain unchanged. **Inference:** high velocity camera motion means per-frame screen-space tile lists are generally invalidated, and the extra moving-car rebuild can dominate small scenes. Preserve existing compute wheel deformation before any projection/bin pass.
- **LOD and crossfades:** Splat opacity participates in contribution culling and front-to-back accumulation. Crossfade fades must be applied before alpha culling/depth output. Stream pool updates invalidate the tile lists. The fixed repair thresholds from paper may not match SOG scene depth distributions.
- **Car effects, shadows, depth and post:** Clearcoat/SH/car sunlight must shade the same fragments and color space. The current analytic shadow proxy is evaluated inside splat shading, so a compute path must preserve its attenuation and clearcoat occlusion. TileGS outputs color, alpha, and last contributing ID in its described raster path, not this engine's exact solid-core depth prepass. A prototype must retain or recreate both car and level depth targets with the current alpha cutoffs (0.8 for the car and 0.5 for the level); otherwise mutual occlusion, car sharpening mask, DOF and post effects change. Direct screen presentation is downstream and independent.

## License / availability

The [arXiv paper](https://arxiv.org/abs/2609.03613) and its supplementary material describe the algorithm and CUDA implementation settings. I found no official source-code repository or explicit software license linked from the primary arXiv record during this review. Treat a port as an independent implementation and verify the authors' code/license availability before any code reuse. Cite the paper if implemented. The benchmark comparator gsplat is Apache-2.0, but that license does not extend to TileGS or establish any license for a prospective port.

## Smallest falsifiable prototype

Do not begin by replacing the main renderer. Add an isolated diagnostic compute raster path for a bounded 128x128 crop of one resident level scene with a modest maximum entry count and 16x16 tiles. Reuse exact current projected centers, covariance, opacity, color and baseline depth keys; build tile-local bins and run one tile compute workgroup. Implement K=8 first (then K=64 only if measurements justify it) and exact-sort all bins as a correctness baseline; add the selective repair policy second. This isolates overhead and output differences without the confound of new projection math. Next test one full production-resolution level frame and then the car/depth composition.

**Pixel gates:** (1) with all bins exactly repaired, compare against current ordered quad output; record per-channel max/mean error, PSNR/SSIM and alpha/depth differences; (2) with selective repair, bound image changes (suggest max absolute 1/255 for RGB on stable opaque regions, separately report transparent edges) and inspect camera-motion sequences for flicker; (3) verify LOD fade endpoints/intermediate frame, wheel pose, car/level occlusion, shadow mask, DOF and car sharpening. Compare both still and orbit references.

**Timing gates:** browser-only paired 1280x720 Saburi and Delft fixed-LOD runs, same WASM, features, and harness. Measure complete frame median and p95, operation counts and bytes; inspect timestamps without adding overlapping spans. Prototype success requires >=5% median full-frame win on both scenes, no >3% p95 regression, and all pixel gates. Report bin-build, scan/scatter, repair and raster counts individually, but treat the complete frame as the result. The paper's CUDA result is not a browser acceptance result.
